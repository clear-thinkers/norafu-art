# Pending Artwork Prepopulation Design

## Goal

`pending.csv` is the staging file for artwork metadata. The prepopulation process should find every artwork image that has been copied into `src/assets/images/` but has not yet been published as `src/content/artworks/[id].json`, then add a CSV row for each unpublished artwork ID.

When AI is available, the row should be filled with a draft title, description, medium, and tags so the human editing step starts from useful copy instead of a blank line.

## Source of Truth

The process treats these files as canonical:

| Source | Role |
| --- | --- |
| `src/assets/images/YYYYMMDD*.JPEG/JPG/PNG` | Candidate artwork inventory |
| `src/content/artworks/[id].json` | Published artwork inventory |
| `pending.csv` | Human-editable staging queue |

An image is considered pending when:

1. Its basename matches `YYYYMMDD` or `YYYYMMDD_suffix`.
2. It has a supported image extension: `.JPEG`, `.JPG`, `.jpeg`, `.jpg`, `.PNG`, or `.png`.
3. There is no matching JSON file in `src/content/artworks/`.

Files such as `about.JPEG`, `profile.JPG`, and `index.js` are ignored because they do not match the artwork ID pattern.

## Script

The implementation lives in `scripts/prepare-pending-artwork.mjs`.

Common commands:

```bash
npm run artwork:prepare
npm run artwork:prepare:replace
```

`npm run artwork:prepare` appends missing unpublished artwork rows and leaves existing CSV rows alone.

`npm run artwork:prepare:replace` rewrites `pending.csv` so it only contains unpublished artwork IDs. This is useful after old pending rows have already been imported and published.

## AI Drafting

The script uses AI when `OPENAI_API_KEY` is set, or when `--ai` is passed. It sends each unpublished artwork image to the OpenAI Responses API along with nearby historical artwork entries. The historical entries are used to match:

- short English descriptions
- natural Simplified Chinese copy
- existing title style
- existing medium values
- existing tag vocabulary

The model returns structured JSON for these CSV fields:

- `title_eng`
- `title_ch`
- `description_eng`
- `description_ch`
- `medium`
- `tags`

The `id` is never generated by AI. It is always derived from the image filename, so every pending row accurately maps back to the artwork asset.

The default model is `gpt-4.1-mini`. Override it when needed:

```bash
OPENAI_MODEL=gpt-5.4-mini npm run artwork:prepare
```

If AI is unavailable, the script still adds an ID-only row with `medium` set to `marker`, so no unpublished artwork is missed. Use `--require-ai` when a failed AI draft should stop the process instead.

If ID-only rows already exist, set `OPENAI_API_KEY` and run:

```bash
npm run artwork:prepare -- --fill-existing
```

That fills existing unpublished rows that are missing required title or description fields.

## Safety Rules

- The script does not create or update published JSON files.
- The script does not resize, rename, or move images.
- Existing CSV rows are preserved unless `--replace` is used.
- Existing rows are not modified unless `--fill-existing` is used.
- AI failures add an ID-only row instead of dropping the artwork from the queue.
- The CSV is written as UTF-8 with BOM for better Excel compatibility.

## Review Workflow

1. Copy new artwork images into `src/assets/images/`.
2. Run `npm run artwork:prepare`.
3. Review and edit generated rows in `pending.csv`.
4. Run `npm run add`.
5. Preview with `npm run dev`.
6. Publish with `npm run deploy`.

AI output should always be treated as a draft. The human review step is where family context, exact titles, intentional jokes, and corrections should be added before publishing.
